# Codex 临时工作区文件整理与目录导航约定

这个目录是一个长期使用的临时工作区，用来存放不同会话、不同任务产生的文件。

主要目标只有两个：

1. 不让各种文件散落在工作区根目录。
2. 使用根目录 `README.md` 记录各个任务文件夹，方便以后查找。

## 文件存放

- 每个会产生文件的任务，尽量使用一个名称清晰的独立文件夹。
- 同一个任务后续产生的源码、文档、图片、下载文件、输出结果和临时文件，继续放在这个任务文件夹里。
- 不要把普通任务文件直接散落在工作区根目录。
- 根目录主要保留公共文件，例如：
  - `AGENTS.md`
  - `README.md`
- 如果用户明确指定了文件路径、项目目录或已有文件位置，以用户要求为准。
- 修改已有项目时，可以直接在原项目目录中工作，不需要为了符合本规则重新复制或移动项目。

## README 导航

根目录 `README.md` 用作整个工作区的目录导航。

创建新的任务文件夹后，在 `README.md` 中简单记录：

- 文件夹名称或链接；
- 这个文件夹是做什么的；
- 主要文件或入口是什么。

记录保持简短，主要目的是以后能快速知道每个文件夹里有什么。

`README.md` 只是文件导航，不需要记录详细任务上下文、待办事项、开发进度或聊天历史。

## 默认不要整理工作区

除非用户明确提出要求，否则不要主动整理整个工作区。

默认不要：

- 批量移动旧文件；
- 重命名旧文件或旧文件夹；
- 合并任务目录；
- 删除历史文件；
- 清理缓存、日志或安装包；
- 归档旧任务；
- 为了让目录更整齐而扫描和调整其他任务；
- 递归检查整个工作区。

完成当前任务时，只处理当前任务需要的文件。

新增任务文件夹后，可以正常更新 `README.md` 导航，这属于维护目录，不算整理工作区。

只有用户明确提出类似以下要求时，才进行整体整理：

- “整理一下工作区”
- “把这些文件分类”
- “清理一下目录”
- “重新整理 README”
- “把旧项目归档”

整理时只处理用户要求的范围，不随意删除可能有用的文件。

## 会话与任务

- 默认把新的会话视为新的任务。
- 不因为文件位于同一个工作区，就自动认为不同文件夹属于同一个项目。
- 当前会话继续处理同一个任务时，优先使用已经建立的任务文件夹。
- 如果只是简单问答，没有产生文件，可以不创建新的任务文件夹。
- 如果任务目录中存在自己的 `AGENTS.md`，在该目录内优先遵循更具体的约定。

## 操作原则

- 只读取和修改当前任务需要的内容。
- 不随意修改其他任务留下的文件。
- 不因为发现其他目录有问题，就顺手修复或整理。
- 不确定文件属于哪个任务时，先做必要的局部检查，不要大范围扫描。
- 用户已有的文件和改动默认保留。

## 交付

- 默认使用中文沟通，用户另有要求时除外。
- 完成任务后，简单说明：
  - 做了什么；
  - 主要文件放在哪里；
  - 如有必要，说明如何使用。
- 不需要为了写交付说明而额外整理整个工作区。
